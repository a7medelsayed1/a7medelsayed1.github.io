01Neoxero · E-commerce · Flutter

zeyada

A family of e-commerce apps for the Saudi market, built from one reusable architecture.

ContextE-commerce apps on a Saudi e-commerce platform
StackFlutter, Dart, Clean Architecture, Bloc
My roleBase architecture and the home-screen data layer

Problem

Launch several similar stores without copying code, and without a home-page API from the platform.

Architecture

A reusable modular base using Clean Architecture and Bloc, so a new store is mostly configuration and theming.

The hard part

The platform exposed the home page only as server-rendered HTML, with the section data embedded as an escaped JSON string and no schema. I parse the HTML, extract each section by its data attribute, decode the JSON, filter by visibility and platform rules, map each section into a typed entity and return them in order. The app renders the home screen as if it were API-driven.

Not every system is API-driven. The skill is understanding how data reaches the UI.

02Neoxero · Magento · Native channels

Ashwered

A Flutter e-commerce app on Magento GraphQL where payments needed a hybrid approach.

ContextE-commerce app for the Saudi market
StackFlutter, Kotlin, Swift, Magento GraphQL, Firebase
FeaturesCatalog, filtering and sorting, wishlist, cart, checkout, order tracking, AR/EN, push notifications

Problem

The available Magento payment modules caused problems in the app.

Solution

I split payments by method. Some methods run in a WebView and keep the module's own flow. The others use native channels, Kotlin on Android and Swift on iOS, connected to Flutter.

When a third-party backend limits you, choose a pragmatic hybrid per case instead of forcing one approach everywhere.
